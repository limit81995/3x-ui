# 项目规范

## 上游基础与扩展

上游为 `MHSanaei/3x-ui`，本仓库为 `limit81995/3x-ui`。在上游持续维护期间，按“原项目基础 + 独立扩展”维护：原有功能尽量跟随上游，扩展独立封装，仅在必要位置接入，减少以后合并上游时的冲突。

- 保留已实现的 HTB 端口限速、前端和 API 设置、数据库保存及每分钟规则校准；限速逻辑集中在 `internal/tclimit` 等扩展模块。
- 优先复用上游的安装、更新、构建和发布流程。已有流程能覆盖需求时，不另建重复脚本、工作流或配置。
- 安装、更新、版本检查及相关脚本下载默认使用本仓库的源码和 Release，不回退到上游产物覆盖扩展。保留限速所需的系统依赖及内核模块配置。
- 保持官方 `docker-compose.yml`，通过 `docker run` 满足本地特殊启动需求；仅在明确需求确实要求修改 Compose 时调整。
- 不因 fork 而批量修改 Go 模块路径、原有命名或真实第三方依赖来源；不夹带与当前需求无关的重构和功能。

## 维护变更

先确认上游已有实现，再确定最小改动范围。删除重复辅助入口时同步清理引用和文档，保留功能所需代码与验证。合并上游时保留扩展的数据和行为，数据库变更兼容已有数据，不覆盖或重写已发布的迁移。

只有确认上游停止维护后，才重新评估独立维护策略；不能仅因一段时间没有提交就默认放弃与上游对齐。用户后续的明确要求优先于本规范。
